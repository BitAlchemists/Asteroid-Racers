The scripted controller alone scores 52.6. Evolution on this task (rock-in-line + point-to-point)
does not improve the residual controller's exam3 after the first generations: what it learns there
(fewer crashes than scripted: 35.6 against 44.0 per race) is paid for elsewhere. Any gain has to
come from what the training asks for, which is batch B's question.

### Descriptive: residual + progress against batch A's residual-only arm (not a test)

Seeds 1–10, g150, exam3 re-scored with `npm run exam3` (it matches the in-run exam3 exactly):
residual only (train-495..504) IQM **48.8**, residual + progress (train-545..554) IQM **50.6**,
paired effect +1.8 [−1.8, +4.8], 5 of 10 seeds better. The 20-seed IQM of the new baseline is 50.4.
**Caveat:** different runs and seed counts, and the progress key changes every lineage from
generation 1 on, so the pairing by seed is nominal. No sign that progress hurts, and no
clear gain on exam3. Its benefit in batch A was on multi-target skills (race-legs, chain).

### Collapses (seed 5 and others)

Screen over every exam generation of all 40 runs: exam v2 checkpoints below 0.6.

- **train-549 (seed 5, baseline) g150:** exam v2 checkpoints 0.28, crashes 536, exam3 42.9. The
  same seed and generation as batch A's train-499 (0.36). Both g150 winners **freeze**: in about
  half the races they move about 70 units from the start and then stand still for the full 180 s
  with no crash (median over the stuck races; local exam v2 with traces). g145–g149 of both runs
  are normal (0.75–0.93). See `doc/HISTORY.md` for the analysis.
- **train-569 (seed 5, +rotation 20) g150:** no freeze (0.92, exam3 47.5).
- Other drops: train-557 (seed 13) g50 0.53 with 630 crashes (freeze-like), g100/g125 0.49/0.52
  (more crashes); train-576 (seed 12) g75 0.53, 1,581 crashes, exam3 28.5 (crash loop). All
  recover at the next exam.
- exam3 shows single-exam dips of 10–20 points in other runs (train-566 g100/g125 36.3/34.8,
  train-579 g50 31.2, train-552 g50 32.0). Each is one generation's winner; the runs recover.

### Recommendation (not signed off; the decision is the user's)

1. **Do not adopt rotation 20 on the strength of exam3:** it doesn't win by the rule. If fewer
   crashes matter more than finish time for the game (bots that crash less look better to
   players), it is a defensible choice by judgement: −20 % crashes per race at an unchanged score.
2. **Keep the baseline as it is** for batch B (already running without rotation).
3. Take the flat exam3 curve seriously: on this task the network learns crash avoidance, not
   racing. Batch B's tiered and generated curricula are the direct test of that.
4. The one-generation freezes (seed 5) argue for judging a run on more than one generation's
   winner, for example exam3 averaged over g125–g150, or `reevaluate`. That would be a change to
   the decision rule, for the user to decide before a later experiment, not for this one.
